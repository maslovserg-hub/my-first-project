# Правила работы с проектом

## Структура файлов

- Каждая страница — **один самодостаточный HTML-файл**: весь CSS и JS встроены внутрь через `<style>` и `<script>`.
- Внешние CSS/JS-библиотеки **не используются** (никаких CDN, jQuery, Bootstrap и т.д.).
- Шрифты Google Fonts допускаются через `@import` или `<link>` — это исключение из правила выше (уже используются в проекте).
- Изображения встраиваются **base64** прямо в HTML, чтобы файл был полностью автономным.
- Файл должен работать при открытии напрямую из браузера (file://) без сервера.

## Дизайн

В проекте два визуальных языка — выбирать по контексту страницы:

### «Тёмный космос» — лендинг, тарифы и все новые страницы по умолчанию
- Фон: `#0a0a14` (тёмно-синий/фиолетовый градиент)
- Акценты: фиолетовый `#7c3aed` → синий `#3b82f6` → зелёный `#10b981`
- Текст акцента (градиент): `#a78bfa` → `#60a5fa` → `#34d399`
- Кнопки: градиент фиолетовый → синий, радиус 50px
- Карточки: `rgba(255,255,255,0.04)`, рамка `rgba(255,255,255,0.08)`

### «Тёмное золото» — только визитка
- Фон: `#0a0a08`
- Акценты: тёплое золото `#c8a84b`, `#f0c060`, `#a07830`
- Шрифты: Cormorant Garamond (имя) + Raleway (остальное)

### Общее для обоих стилей
- Анимации — плавные, через CSS `transition` и `@keyframes`. Без резких скачков.
- Все декоративные эффекты (свечение, градиенты, тени) — через чистый CSS.

## Адаптивность

- Вёрстка обязана корректно выглядеть на мобильных (от 320px) и на десктопе.
- Используем CSS Grid и Flexbox — без фиксированных пиксельных ширин там, где можно обойтись без них.
- Размеры шрифтов — через `clamp()` для плавного масштабирования.
- Интерактивность адаптируется под устройство: на десктопе — hover, на мобильном — tap.
- Обязательный мета-тег: `<meta name="viewport" content="width=device-width, initial-scale=1.0">`.

## Текст и контент

- Стиль текста — **простой и дружеский**: так, как говорят живые люди, а не официальные документы.
- Никакого канцелярита: вместо "осуществляется взаимодействие" → "работаем вместе".
- Заголовки — конкретные и с пользой для читателя, не абстрактные.

## Процесс работы

- Перед созданием нового файла — **сначала описать план**: что будет на странице, из каких секций, какая логика.
- Перед правкой существующего файла — **сначала прочитать** его целиком.
- Не добавлять функциональность, которую не просили.
- Не рефакторить код "по пути" — только то, что нужно для задачи.

## Git

- Коммиты делаем только когда пользователь явно просит.
- Файл `qr_landing.png` добавлен в `.gitignore` — не трогать это правило.
- Чувствительные файлы (PDF, личные данные) в коммиты не включать без явного разрешения.
